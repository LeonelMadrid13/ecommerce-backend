# Learning Notes - 2026-04-07

## Context

- Consolidated E2E testing workflow for an e-commerce backend under TDD/SDD constraints.
- Main challenge: parallel PRs were repeatedly conflicting on a single E2E spec file.

## Key Decisions

1. **Apply RBAC route protection explicitly on sensitive endpoints**
   - **Why**: API behavior had to match PRD security requirements.
   - **Tradeoff**: tighter authorization checks increase short-term test setup complexity.

2. **Split E2E tests by domain (`auth`, `authorization`, `products`)**
   - **Why**: reduce merge conflicts and improve review clarity.
   - **Tradeoff**: more files to maintain, but significantly cleaner collaboration.

3. **Use rebases to align long-lived test branches with `master`**
   - **Why**: avoid drift and remove obsolete commits touching deleted files.
   - **Tradeoff**: requires force-with-lease discipline and careful conflict handling.

## Technologies Used

- **NestJS** for modular HTTP layer and guards.
- **Jest + Supertest** for E2E contract testing.
- **TypeScript strict checks** to catch unsafe mock typing in specs.
- **GitHub CLI** for PR lifecycle management.

## Concepts Reinforced

- Difference between **401** (unauthenticated) and **403** (authenticated but unauthorized).
- Test architecture influences delivery speed as much as production architecture.
- Verification quality depends on both runtime evidence and traceability artifacts.

## How to Explain This Work

### Short version

We stabilized backend E2E testing by aligning auth/authorization behavior with the PRD and splitting tests into domain-focused files, reducing PR conflicts and improving maintainability.

### Technical version

We moved from a monolithic E2E file to domain suites (`auth.e2e-spec.ts`, `authorization.e2e-spec.ts`, `products.e2e-spec.ts`), enforced RBAC behavior coverage (201/403/401), and normalized branch state through rebases after merge. This improved CI reliability and collaboration while keeping strict TypeScript and E2E validation green.
