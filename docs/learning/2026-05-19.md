# Learning Log - 2026-05-19

## 1) Aprendizajes del día

- El costo de `bcrypt` conviene configurarlo por ambiente para equilibrar seguridad y performance.
- Al introducir configuración en un servicio, los tests unitarios deben mockear o proveer esa configuración.
- Los cambios de dependencias con pnpm deben mantener `package.json` y `pnpm-lock.yaml` sincronizados y con diff revisable.
- Los artefactos locales/generados no deben mezclarse con cambios de código.

## 2) Decisiones tomadas y por qué

1. **Configurar bcrypt rounds por entorno**
   - **Por qué**: facilita ajustar seguridad/performance sin modificar código.
   - **Tradeoff**: requiere validación de configuración y tests más explícitos.

2. **Mantener higiene de lockfile**
   - **Por qué**: un lockfile con miles de líneas reescritas oculta el cambio real y dificulta la review.
   - **Tradeoff**: a veces exige restaurar y aplicar el cambio mínimo manualmente.

3. **Ignorar artefactos locales**
   - **Por qué**: evita versionar estado de herramientas locales o exports temporales.
   - **Tradeoff**: los artefactos que sí sean oficiales deben nombrarse y documentarse explícitamente.

## 3) Tecnologías usadas y por qué

- **NestJS ConfigService** para configuración por ambiente.
- **bcrypt** para hashing seguro de contraseñas.
- **Jest** para validar comportamiento unitario.
- **pnpm overrides/audit** para control y revisión de dependencias.

## 4) Términos que debo dominar

- bcrypt rounds
- lockfile hygiene
- dependency override
- transitive dependency
- generated artifact

## 5) Cómo explico lo que hice

### Versión simple

Hicimos que el costo de seguridad del hashing de contraseñas pueda ajustarse desde configuración, sin tocar el código cada vez. También revisamos que el commit quede limpio y no incluya archivos locales generados por herramientas.

### Versión técnica

Se integró configuración para los rounds de bcrypt, se ajustaron tests unitarios para cubrir configuración válida e inválida, y se auditó el árbol de dependencias con un override controlado de `fast-uri`. Además se protegió el repo contra artefactos locales de Pi/Postman mediante `.gitignore`.
